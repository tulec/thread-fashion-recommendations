# THREAD — Fashion Recommendation Lab

Персональные рекомендации одежды: от истории покупок до работающего демо.
Портфолио-проект для Junior Data Scientist / ML Engineer на задаче
[H&M Personalized Fashion Recommendations](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations).

**Текущий статус:** обучение на реальных данных H&M успешно завершено в Kaggle;
локальное демо работает. Проверены 5000 покупателей за 16–22 сентября 2020 года,
seed=42. Обучаемая модель улучшает популярность, но уступает фиксированному гибриду.

| Метод | MAP@12 |
|---|---:|
| Популярные товары | 0.008543 |
| Гибрид с фиксированными весами | 0.029297 |
| Обучаемая модель | 0.027654 |

Разница обучаемой модели с популярностью: 0.019111; 95% парный bootstrap-интервал
[0.015431; 0.022632]. Оценка проведена на 5000 из 68984 покупателей проверочной
недели, включая 1275 без истории в окне. Это офлайн-результат одной недели,
не рост продаж и не официальный балл Kaggle. [Подробный разбор](docs/RESULTS.md).
Синтетический режим нужен для запуска без закрытых данных и маркируется отдельно.

## Что делает система

Предсказывает 12 товаров, которые покупатель может приобрести в следующие 7 дней.

1. Формирует кандидатов из популярности за последние недели, повторных покупок
   и связей между последовательными покупками.
2. Сравнивает популярность, гибрид с фиксированными весами и обучаемую модель
   `HistGradientBoostingClassifier` (поточечная оценка кандидатов).
3. Оценивает MAP@12, полноту кандидатов, охват каталога и cold start.
4. Показывает рекомендации и историю условного профиля в Streamlit.

Метаданные категорий используются как дополнительный сигнал. Фотографии,
персональные характеристики и адреса покупателей не требуются. Карточки демо
используют цветовые обозначения, а не изображения товаров.

## Быстрый запуск

Python 3.10+. Из корня проекта:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m fashion_recs.pipeline demo
python -m streamlit run app.py
```

Демо создаёт искусственные покупки и явно маркируется **SYNTHETIC**. В нём можно
переключать профили, сравнивать персональную выдачу с популярностью и проверять
сценарий нового покупателя. Файлы генерируются в `artifacts/demo/`.

## Реальные данные H&M

Откройте [Data](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/data)
и ознакомьтесь с [правилами](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/rules).
Если принимаете их, выполните присоединение в своём аккаунте. Затем скачайте
`transactions_train.csv`, `articles.csv`, `sample_submission.csv` в `data/hm/`.
Архив изображений на десятки гигабайт не нужен. `customers.csv` тоже не требуется.
Не коммитьте исходные данные, веса и файлы рекомендаций реальных покупателей.
Возможность публикации производных артефактов проверяйте по правилам H&M.

```powershell
python -m fashion_recs.pipeline train --data-dir data/hm --output artifacts/real
```

Загрузчик сканирует даты, затем читает CSV частями и оставляет последние 98 дней.
По умолчанию обучение использует до 3000 покупателей, оценка — до 5000;
выборка случайная с seed=42. В отчёте записываются её размер и исходная популяция.
Это ограниченный по вычислениям старт, а не оценка на всех покупателях.

```powershell
python -m fashion_recs.pipeline train --data-dir data/hm --output artifacts/real --train-users 10000 --eval-users 20000
python -m fashion_recs.pipeline submit --model artifacts/real/model.pkl --sample data/hm/sample_submission.csv --output artifacts/submission.csv
```

`--eval-users 0` оценивает всех покупателей проверочной недели. Полное создание
submission может занять продолжительное время: для каждого профиля выполняется
индивидуальное ранжирование. Команда создаёт CSV локально и не отправляет его.
Синтетическую модель использовать для submission запрещает сам код.

После реального обучения демо автоматически выберет `artifacts/real/demo.json`.
Можно задать другой путь через переменную `FASHION_DEMO_PATH`. Не публикуйте
реальные артефакты без проверки условий использования данных.

## Проверка по времени

Если последняя доступная дата — D, то:

- признаки обучающей выборки используют даты до D−13;
- метки обучения: [D−13, D−6);
- признаки проверки используют даты до D−6;
- метки проверки: [D−6, D+1).

В коде удобнее считать исключающую верхнюю границу `end = D+1`: обучение
начинается `end−14`, проверка — `end−7`. У всех интервалов правая граница исключена.
Гиперпараметры фиксированы до проверки. Случайное внутреннее разбиение sklearn
для early stopping отключено. Будущие покупки не входят ни в граф, ни в популярность,
ни в историю. После оценки только статистики для выдачи обновляются до `end`;
обучаемая модель остаётся той, которую проверяли.

Все методы оцениваются на одинаковых покупателях, включая новых относительно
98-дневного окна. Как и в задаче H&M, оценка условна на факте покупки в целевой
неделе. Есть 95% парный bootstrap-интервал разницы MAP@12 с популярностью;
он отражает выборку покупателей одной недели, но не сезонную неопределённость.

## Результаты и ограничения

После запуска `artifacts/<режим>/report.md` и `report.json` содержат реальные
измерения соответствующего запуска. `manifest.json` содержит SHA-256 артефактов.
Числа в таблице выше получены из приватного запуска Kaggle `364262984`.

- Точечный классификатор — доступная первая модель, не специализированный LambdaRank.
- Новые артикулы без покупок не попадают в кандидаты; это следующее направление
  развития через контент товаров, в том числе изображения.
- Cold start определяется относительно загруженного окна, не всей истории H&M.
- Одна проверочная неделя не заменяет несколько временных окон и A/B-тест.
- Подписи в демо описывают доступные сигналы, а не причинное объяснение модели.
- Выборки, seed, даты и параметры сохранены; побитовая воспроизводимость между
  разными версиями библиотек не гарантируется.
- `model.pkl` — внутренний доверенный файл; не загружайте чужие pickle-файлы.


выдачи, сохранение нулей в артикулах и полный цикл создания артефактов.
