# Расширение кандидатов и проверка по неделям

## Зафиксированный протокол

Код эксперимента опубликован до просмотра его результатов. Сравниваются два
генератора кандидатов и три метода скоринга: популярность, гибрид с исходными
фиксированными весами и исходный градиентный бустинг без изменения параметров.

Новый генератор использует 120 популярных товаров вместо 60, последние 24
уникальные покупки вместо 12, до 40 популярных товаров в каждой из двух любимых
категорий, варианты до 12 ранее купленных моделей и пары среди последних четырёх
уникальных покупок за 28 дней. На один профиль оставляется не более 480 кандидатов.
Каталог сам по себе не добавляет будущие товары: артикул должен встречаться в
покупках до соответствующей границы времени.

Это совместное изменение нескольких источников. Без отдельной абляции нельзя
приписывать выигрыш одному из них.

## Временные окна

| 2020-09-16 | Повторная контрольная проверка |

Каждая проверка использует до 5000 покупателей. Обучение скоринга — до 3000
покупателей из непосредственно предшествующей недели. В каждой паре сравнений
покупатели одинаковые; seed=42. Все признаки берутся строго из предыдущих 98 дней.
Для этого загрузчик читает 133 дня данных, покрывая и самое раннее обучающее окно.

В первой версии проекта использовался общий загруженный отрезок 98 дней. Здесь
для каждого разбиения используется полное скользящее окно 98 дней. Поэтому
исходный метод пересчитывается, а его прежний балл не подставляется в сравнение.

Победитель выбирается по среднему MAP@12 трёх ранних недель среди четырёх пар:
исходный/расширенный генератор × гибрид/обучаемый скоринг. Последняя неделя не
участвует в выборе. Её период уже оценивался в первой версии проекта; он не
является новым, ранее не использованным тестом.

## Метрики

MAP@12 оценивается по уникальным реальным покупкам каждого покупателя. Полнота
кандидатов — средняя по покупателям доля их целевых артикулов в наборе кандидатов.
Для новых покупателей выдача остаётся популярностной; расширение общего набора
кандидатов само по себе не меняет этот fallback.

Для гибрида и обучаемого скоринга рассчитываются 95% парные bootstrap-интервалы
разницы с исходным вариантом в той же неделе. Они описывают выборку покупателей,
но не сезонную изменчивость. Пользователи разных недель могут пересекаться.

Дополнительные показатели cold/warm в отчёте относятся к обучаемому скорингу.
Полнота кандидатов характеризует генератор независимо от способа ранжирования.

Файлы `comparison.partial.json` и `comparison.json` содержат результаты и даты
источников признаков. Промежуточный файл сохраняется после завершения каждой недели.
Финальный файл дополнительно фиксирует выбранный вариант и полный протокол.

## Воспроизведение

В Kaggle импортируйте `notebooks/hm_rolling_comparison.ipynb`, прикрепите официальные
данные H&M и выполните Save & Run All. CPU достаточно. Изображения не читаются;
предсказания в соревнование не отправляются.

После сравнения ноутбук создаёт приватное демо выбранного варианта. Исходные
истории, идентификаторы и веса не публикуются в GitHub.
